# Markdown 正文图片交付：调整方案与实现

## 目标

以最终回复中的 Markdown 图片节点为交付入口，例如 `前文 ![首页](./screenshots/home.png) 后文`。不再要求模型调用 `publish_image`；图片属于正文，而非全文结束后统一追加的附件。

## 当前实现

1. 删除 `PublishImageTalent`、`PublishImageExtension` 和 `ImagePublishTurn`，移除工具注册和专用 token。
2. `ChannelReply` 使用 flexmark 核心解析最终 Markdown，记录图片节点源码区间；支持内联与引用式图片，忽略代码块、行内代码和转义示例。不改聊天历史或 Web 原文。
3. `ImageSnapshots` 仅对明确引用的工作区本地 PNG/JPEG 安全读取。相对本轮 CWD，URI percent 编码只解码一次，字面 `+` 不变，片段不参与路径解析。拒绝越界、编码目录穿越、编码路径分隔符、挂载别名及符号链接。
4. 只有已绑定飞书或钉钉才准备图片快照。读取/解码在会话锁外完成，锁内二次校验请求身份和终态，取消、异常、旧轮和准备期间 HITL 不会提交图片。
5. 飞书在原 FIFO 任务内上传取得 `image_key`，原位替换为 `![说明](image_key)`，复用 post/md 分片与重试。
6. 钉钉同步上传取得 `media_id`，原位替换为 `![说明](media_id)`，复用 sampleMarkdown 分片与重试。不增加钉钉队列。
7. 相同本地图片只读取一次，每渠道只上传一次（包括失败缓存）；正文重试不重复上传，成功分片不整轮重放。失败仅降级当前节点，不丢周围正文。
8. 渠道替换时记录最终正文中的真实图片/链接范围，分片器直接使用这些范围，不按平台 ID 再做正则猜测，代码示例不受误伤。分片计入实际序号长度并避免拆 UTF-16 代理对；超长节点在任何正文发送前原位降级，其他节点保持完整，不重复上传。

## 外链和失败策略

- 不新增服务端下载、图床、压缩、HTML 图片或通用富文本框架。
- 钉钉保留通过校验的 HTTPS 图片；飞书将 HTTP/HTTPS 图片转换为可点击链接。
- 当前外链策略拒绝 userinfo、query、fragment 和无效 URL，含签名查询参数的图片也会保守降级。
- 失败使用安全说明和固定原因，不回显本地路径、服务端响应或凭据；纯文本降级不输出 image_key/media_id。
- 图片独占的引用定义在渠道渲染后删除，避免原路径残留；与普通链接共享的定义保留，避免破坏显式普通链接；Web 原文不变。
- 飞书队列拒收向调用方抛出明确异常，由上层记录，不在队列外补发破坏顺序；不承诺队列满时用户必定收到通知。文本广播隔离单渠道异常；取消流程通过 finally 保证实际 dispose，不依赖通知成功。
- 飞书消费者中断时保留中断标记并退出，清理剩余项、释放容量并记录丢弃数量；不把未执行项当作成功，不自动重投绕过执行器关闭语义。这不是可靠投递队列，关闭/中断时不保证排队消息送达。

## 资源和生命周期边界

- 每轮最多 5 张不同本地图片，总压缩字节不超过 25MiB；单图最多 10MiB，最长边 12000、最多 1600 万像素；最多两个并行图片加载任务。
- 单个图片目标最长 16384 个 UTF-16 单元，每轮最多尝试 20 个不同规范本地路径（失败也计入），成功和失败结果均在本轮复用。百分号解码按连续编码段线性处理；完整读取前检查并预留剩余预算，失败归还，打开文件并复核大小后才分配内容数组。
- 钉钉另限单图 1MiB，这是保守产品限制，不声称是所有企业应用的平台上限。
- 飞书保留在途任务/图片字节预算，包含执行中任务。准备阶段、钉钉并发快照和上传临时缓冲不受全进程驻留字节预算约束；不能把上述限制描述为 JVM 总内存上限。本次不引入租约或制品生命周期管理器。
- 最终回复准备时源文件必须仍存在；快照完成后删除或覆盖源文件不影响已准备交付。
- 成功终态领取是交付提交点，提交后的取消不撤回渠道排队快照或已发送消息；准备期间取消仍会阻止成功交付。
- Java 8 NIO 的前后身份检查不构成抵御恶意并发文件系统写入的强原子隔离。
